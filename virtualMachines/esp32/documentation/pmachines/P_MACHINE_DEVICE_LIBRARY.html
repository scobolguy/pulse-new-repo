P‑Machine Device Library

The P‑Machine Device Library is a modular, extensible hardware abstraction layer designed to support a wide range of physical devices including switches, pushbuttons, encoders, relays, PWM outputs, analog sensors, digital sensors, and more. It provides a unified interface for device interaction, a common request/response protocol, and a clean binding mechanism into the P‑Machine runtime.

1. Architectural Overview

The library is built around a universal device interface (IDevice) that all device types implement. This ensures consistent behavior across device categories and allows the P‑Machine to interact with all devices using a single request model.

  • Unified device lifecycle (init, tick, request handling)
  • Common request/response protocol
  • Event emission for asynchronous device changes
  • Device registry for dynamic binding into the P‑Machine
  • DSL integration for declarative device definitions

2. Universal Device Interface

All devices implement the IDevice interface. This interface defines the lifecycle, request handling, metadata, and event emission capabilities required by the P‑Machine. 


class IDevice {
public:
    virtual ~IDevice() {}

    // Hardware initialization
    virtual void init() = 0;

    // Periodic polling, debouncing, smoothing, sampling
    virtual void tick() = 0;

    // Logical request handler
    virtual bool handleRequest(const std::string& request,
                               const PMsg& args,
                               PMsg& response) = 0;

    // Emit events back into the P‑Machine
    virtual void emitEvent(const PMsg& event) = 0;

    // Metadata
    virtual const std::string& name() const = 0;
    virtual const std::string& type() const = 0;
};

This interface is intentionally minimal but powerful enough to support all device categories.

3. Device Lifecycle

The lifecycle consists of three phases:

Initialization (init())

  • Configures GPIO, ADC, I2C, SPI, PWM, or other hardware interfaces
  • Sets initial device state
  • Allocates buffers or internal structures

Ticking (tick())

  • Debounces switches
  • Reads sensors
  • Processes encoder deltas
  • Samples ADC values
  • Generates events when state changes

Request Handling (handleRequest())

  • Executes logical operations (e.g., set, read, configure)
  • Returns structured responses via PMsg

4. Common Request Library

The request library provides a uniform mechanism for sending logical commands to devices. The P‑Machine uses a DeviceRequestRouter to dispatch requests. 


class DeviceRequestRouter {
public:
    bool dispatch(IDevice* device,
                  const std::string& request,
                  const PMsg& args,
                  PMsg& response)
    {
        return device->handleRequest(request, args, response);
    }
};

This abstraction allows the P‑Machine to remain device‑agnostic.

6. Binding Devices into the P‑Machine

The P‑Machine maintains a registry of devices and provides methods for initialization, ticking, and request dispatch. 


class PMachine {
public:
    void registerDevice(IDevice* dev) {
        devices.push_back(dev);
    }

    void initDevices() {
        for (auto* d : devices) d->init();
    }

    void tickDevices() {
        for (auto* d : devices) d->tick();
    }

    bool sendRequest(const std::string& deviceName,
                     const std::string& request,
                     const PMsg& args,
                     PMsg& response)
    {
        for (auto* d : devices)
            if (d->name() == deviceName)
                return router.dispatch(d, request, args, response);
        return false;
    }

private:
    std::vector<IDevice*> devices;
    DeviceRequestRouter router;
};

7. DSL Integration

Devices can be declared in the P‑Machine DSL using simple declarative syntax: 


device switch front_door pin 14 debounce 20ms;
device relay hall_light pin 5;
device pwm fan pin 12 freq 1kHz;
device temp temp_probe channel 3;

The compiler generates corresponding C++ bindings: 


pmachine.registerDevice(new SwitchDevice("front_door", 14, 20000));
pmachine.registerDevice(new RelayDevice("hall_light", 5));
pmachine.registerDevice(new PwmDevice("fan", 12, 1000));
pmachine.registerDevice(new TempSensorDevice("temp_probe", 3));

8. Device Families and Macros

Device families can be defined using macros or templates to reduce boilerplate and support cluster‑aware placement and replication. 


DEFINE_GPIO_SWITCH(front_door, pin=14, debounce=20ms)
DEFINE_PWM_OUTPUT(fan, pin=12, freq=1kHz)
DEFINE_ADC_SENSOR(temp_probe, channel=3, smoothing=4)

9. Summary

The P‑Machine Device Library provides a robust, extensible foundation for hardware abstraction. Its unified interface, common request model, event system, and DSL integration make it suitable for complex distributed systems, cluster‑aware runtimes, and scalable hardware deployments.
