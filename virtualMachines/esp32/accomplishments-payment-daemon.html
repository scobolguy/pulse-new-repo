Pascalish Solution Source

This is the problem-oriented source used by the solution compiler. It describes what the daemon does and which logical resources it uses.

solution payment_ingestion;
problem "Accept MT103 messages, persist them, convert them, and route PACS008 output";

system PaymentSystem;
database MessageStore provider sqlserver table incoming_messages manager db-mssql physical PaymentMessages;
queue IncomingMessages type mt103 direction input manager qm-secondary physical swift.mt103.inbound;
queue OutgoingPayments type pacs008 direction output manager qm-secondary physical swift.pacs008.outbound;
service ConversionService;
conversion MT103ToPACS008 input mt103 output pacs008 map "mt103-to-pacs";
daemon MessageDaemon refresh 2 s reads IncomingMessages writes MessageStore uses ConversionService emits OutgoingPayments;

method process_message(message: mt103): pacs008
steps
  validate message;
  persist message in MessageStore as received;
  convert message using MT103ToPACS008;
  emit result to OutgoingPayments;
end;

Generated Pascalish Execution Shape

The compiler lowers the solution into provider-independent Pascalish constructs. The mapper and router are generated after the daemon body.

database MessageStore type MessageStoreRecord;
table incoming_messages of MessageStoreRecord in MessageStore
  columns (reference: string, payload: string, status: string);

queue IncomingMessages queue<mt103>;
queue OutgoingPayments queue<pacs008>;

var
  message: string;

daemon "MessageDaemon" refresh 2 s;
begin
  dequeue IncomingMessages into message;
  if message <> '' then
  begin
    insert into incoming_messages (reference, payload, status)
      values (message, message, "received");
  end;
end.

mapper "MT103ToPACS008" source "swift-mt103" target "pacs" begin
  { CBDS rules are emitted here from mt103-to-pacs.map }
end;

router "payment_ingestion_conversion" input "IncomingMessages" begin
  output "OutgoingPayments"
    when "output := 1"
    transform "output := map('MT103ToPACS008', src);";
end;

Execution steps

  1. The solution compiler parses the logical declarations and creates a semantic IR.
  2. Pascalish is generated with a daemon, input/output queues, a database table, and a mapper.
  3. The Pascalish compiler emits pcode and a program map.
  4. The PMachine matches IncomingMessages and reads the input payload.
  5. The daemon emits a DB_INSERT delivery for the incoming message.
  6. The router invokes ROUTE_MAP_RUN for MT103ToPACS008.
  7. The mapper applies the CBDS rules and creates PACS008 output.
  8. The output is delivered to OutgoingPayments.
  9. The deployment manifest translates that logical queue to swift.pacs008.outbound on qm-secondary.
  10. The database binding translates MessageStore to PaymentMessages on db-mssql.
