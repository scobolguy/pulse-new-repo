MT103 Message Flow

Aggregator pipeline from ingress to downstream fanout queues.

1) Ingress API

Producer posts MT103 payload to /api/queue/swift.mt103.inbound/enqueue.

Source: aggregator/src/backend/roles/queueBrokerOpsRoutes.mjs

DOWNSTREAM

2) Queue Enqueue + Route Delivery

Backend resolves leader route and enqueues via enqueueViaRoute; queue data type validation is enforced.

Source: aggregator/backend.mjs

ROUTING WORKER DEQUEUE

3) Routing Engine Processing

Routing worker polls queues with processFromQueue, then applies DSL rules and mapping transforms.

Source: aggregator/router-engine.mjs

MT103 RULE

4) MT103 Inbound to Parsed

Rule mt103-inbound-to-parsed: swift.mt103.inbound -> swift.mt103.parsed.

Source: aggregator/data/router-mapper.dsl

FANOUT

5) Parsed MT103 Fanout

Rule mt103-correspondent-and-lynx-fanout routes one parsed MT103 into two outputs:

Branch A
correspondent.pacs008.outbound
Transform: map("mt103-to-pacs", src)
Branch B
lynx.pacs009.outbound
Transform: map("pacs-to-lynx", map("mt103-to-pacs", src))

Source: aggregator/data/router-mapper.dsl

FINAL

6) Downstream Queue Consumption

Consumers/gateways pick up messages from correspondent and LYNX outbound queues for further processing.

Compact path: swift.mt103.inbound -> swift.mt103.parsed -> {correspondent.pacs008.outbound, lynx.pacs009.outbound}
